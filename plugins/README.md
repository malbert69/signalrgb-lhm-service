# Motherboard plugins

There are **252 plugins**: the original ASUS PRIME Z790-P WIFI plugin plus **251 upstream-derived plugins** below. The new plugins cover 306 exact SMBIOS model strings, including aliases.

The new plugins are **hardware untested**. Their mappings come from the pinned LibreHardwareMonitorLib 0.9.6 tables, not probes of those boards. They require exact manufacturer/model matches, a primary Super I/O chip path, matching raw LHM channel names, and fresh valid readings. Chip alternatives reflect the upstream routing table; they do not certify that every chip is fitted to a board. Secondary Super I/O channels, generic/unknown/AUX labels, and unsupported embedded-controller-only boards are excluded. Where an upstream label occurs on two channels, the display names include channel numbers rather than silently selecting one.

The original [ASUS PRIME Z790-P WIFI plugin](../ASUS_LHM_Temperatures.js) has earlier native sensor validation; version 0.2 SignalRGB integration remains pending.

The root installer detects the motherboard through Windows SMBIOS/CIM, installs only its matching plugin, and backs up other packaged plugins left by older installations. Unknown or ambiguous boards stop installation before service or plugin changes. You can also copy the relevant JS file into SignalRGB's Plugins directory manually. `install-manifest.json` contains installer-only identity metadata generated from the plugins. No catalog or JSON file is needed by the running service or plugins.

## Regeneration

Run `Build.ps1`, then `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Generate-Plugins.ps1`. The extractor checks SHA-256 hashes of the pinned upstream source, evaluates only model-specific table routes against a fake chip, and rejects hardware operations. The generated JS files embed their own board data and a copy of the runtime from the root ASUS plugin. Use `node tools/generate-plugins.cjs --check` to check generated files without downloading sources or opening hardware. The catalog records source hashes and exact model/manufacturer aliases validated against the compiled library. See [NOTICE.md](NOTICE.md).
